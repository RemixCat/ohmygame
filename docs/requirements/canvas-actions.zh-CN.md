# 画板快捷操作与批量生成：需求草案

- 日期：2026-10-14
- 状态：讨论稿，尚未开始功能实现
- 开发分支：`feat/canvas-quick-actions`
- 基线：`upstream/dev`；创建分支时与本地已运行的发布版本代码内容一致
- 适用界面：游戏项目的设计画板，以及 Asset Canvas 素材画板

## 1. 用户目标

用户可以直接从画板上的图片发起常用制作操作，无需每次通过左侧对话让 Agent 创建节点、填写提示词、连接参考图和启动生成。

典型场景：上传一张飞船参考图，从图片右侧拉线到空白位置，选择“三视图”，得到俯视、正视、右视三个独立的图片节点和三个独立文件。每个结果都可以继续编辑、重新生成或用于制作 3D 模型。

左侧对话仍用于复杂任务和自由创作；画板操作与对话共用节点、生成能力、任务记录和素材库。

## 2. 当前已经确认的需求

| 编号 | 需求                 | 用户期望                                                     |
| ---- | -------------------- | ------------------------------------------------------------ |
| R1   | 从图片拉线发起操作   | 拉线到空白处并松开后，出现与来源图片相关的操作菜单           |
| R2   | 图片生成描述或提示词 | 根据参考图生成可编辑文本，方便继续用于图片或模型制作         |
| R3   | 识别图片内物体       | 能发现图中的角色、道具、植物、建筑等元素；输出深度待确认     |
| R4   | 三视图生成           | 一张参考图生成俯视、正视、右视三张独立图片，分别呈现在画板上 |
| R5   | 图片生成 3D 模型     | 自动创建并连接现有 3D 节点，直接配置和运行                   |
| R6   | 不依赖聊天操作       | 固定操作可以通过菜单和按钮完成，不要求发送对话消息           |
| R7   | 兼容现有功能         | 继续支持 Agent 修改画板，复用原有生成与素材库能力            |

## 3. 建议的交互

### 3.1 操作入口

主入口：从有可用图片的节点输出端拉线到空白位置，松开后弹出菜单。

建议增加等价的右键菜单入口，方便不习惯拉线的用户。两种入口调用同一套操作定义。

首版候选菜单：

- 生成描述 / 提示词
- 识别物体
- 生成三视图
- 根据参考图生成图片
- 生成 3D 模型

连接到已有节点时沿用现有的引用关系规则；只有落到空白处时进入快捷创建。取消菜单不创建空节点，不启动生成。

### 3.2 创建与运行

选中操作后，自动创建对应节点、关联来源图，并将节点放到落点附近。显示该操作所需的模型、参数和预设内容，用户可以修改，然后点击“运行”。

建议创建和执行分开：拉线或打开菜单本身不产生模型调用，点击运行才产生请求。批量生成有一个统一的运行入口，同时保留单个节点的生成操作。

模型未配置、参考图片不存在、所选模型不支持该能力时，应在对应操作附近提供清楚的提示和设置入口。

## 4. 各操作的行为

### 4.1 描述 / 提示词

- 输入：来源图片、支持图像输入的语言模型。
- 输出：一个与图片关联的可编辑文本节点。
- 描述内容可涵盖主体、形状、颜色、材质、风格、视角和背景。
- “反向提示词”表示根据画面推测的描述，不声称恢复原始生成提示词。
- 具体菜单命名及是否分别提供“描述”和“生成提示词”，待讨论。

### 4.2 识别物体

以下三种行为需要区分，不能用同一个“提取成功”概念混用：

| 层次     | 输出                               | 对应能力         |
| -------- | ---------------------------------- | ---------------- |
| 识别     | 物体清单及描述                     | 视觉语言模型     |
| 重新生成 | 各物体的独立图片，可补全被遮挡部分 | 参考图生成       |
| 精确抠图 | 原图物体的裁切 / 蒙版 / 透明图片   | 图像分割及后处理 |

建议先生成可勾选的清单，再为选中的物体创建独立图片节点。精确抠图作为单独能力评估，不与参考图重新生成混为一谈。这是首版建议，尚待用户确认。

### 4.3 三视图

- 默认视角：俯视、正视、右视。
- 默认产物：三个独立图片节点、三个独立文件，各自引用同一张来源图。
- 每个视角有独立提示词；共享主体描述、模型和基础尺寸设置。
- 默认构图建议：单主体、统一背景、尽量保持比例与材质一致；不把三视图拼在一个文件内。
- 支持统一启动，分别显示成功或失败，单独重试失败视角。
- 已成功的视角不因其他视角失败而丢失或被自动重新生成。
- 三张图片的结构一致性受模型影响；原图未呈现的部分由模型推测。
- “先生成拼图再裁切”可作为后续模式，首版建议不包含。

### 4.4 图片生成 3D 模型

- 创建已有的 `model-3d` 节点并关联来源图。
- 复用已有服务商、模型、参数、任务恢复和 GLB 结果展示。
- 用户可在运行前选择模型并修改参数。
- 首版不默认要求先生成三视图，也不自动把所有下游节点执行一遍。
- 生成模型后可继续使用现有模型、动画或游戏集成功能。

## 5. 批量任务与结果

- 每个产物显示等待、运行、成功、失败或取消状态。
- 控制并发数量，避免同时发起过多服务商请求；具体默认值待确定。
- 批次运行期间再次点击不会重复创建同一批任务。
- 失败节点显示可理解的错误，支持针对该节点重试。
- 取消行为尊重已有服务商契约；停止本地等待不一定代表远端任务停止或费用退回。
- 菜单创建的一组节点应可一起撤销；撤销布局不暗示已提交的模型任务被撤销。
- 保留已有素材库落盘和项目内副本机制，结果能够跨项目复用。
- 节点与结果使用清楚的名称，例如“飞船－俯视图”，避免只显示通用的 output 名称。
- 切换画板、重新打开项目后，节点、引用、设置和已保存结果仍可恢复。

## 6. 首版建议与后续范围

首版建议包含：

1. 图片拉线到空白处的操作菜单，以及等价的右键入口。
2. 描述 / 提示词生成，复用文本节点和图片引用。
3. 三视图模板、统一启动、单独状态与失败重试。
4. 直接创建并连接图片生成、3D 生成节点。
5. 物体识别清单及后续创建素材节点的方式，按用户选择确定范围。

后续再评估：精确抠图、其他视角模板、用户保存模板、拼图裁切、自动执行依赖链。

完整 ComfyUI 式工作流引擎，包括任意节点算子、循环、复杂条件、缓存及整图调度，不属于当前首版建议。

## 7. 与上游代码的兼容方式

优先复用已有节点类型和文件格式。快捷操作可以先展开为普通文本、图片和 3D 节点，避免为几个固定模板引入全新的画布格式。

现有代码入口：

| 模块         | 文件                                                            | 可复用能力                               |
| ------------ | --------------------------------------------------------------- | ---------------------------------------- |
| 画板和连线   | `src/renderer/asset-canvas-workspace.tsx`                       | 节点创建、引用连接、生成操作、上下文菜单 |
| 画布基础交互 | `src/renderer/editor-canvas.tsx`                                | React Flow 事件、坐标转换、菜单显示      |
| 节点定义     | `src/shared/contracts.ts`、`src/shared/asset-canvas.ts`         | 现有文本、图片、3D 节点和引用类型        |
| 图片描述     | `src/daemon/text-generation.ts`、`src/daemon/app.ts`            | 图像引用与文本生成                       |
| 节点生成     | `src/daemon/canvas-workspace.ts`、`src/daemon/canvas-routes.ts` | 生成任务、历史、取消与重试               |
| 素材保存     | `src/daemon/asset-library.ts`、`src/daemon/projects.ts`         | 素材库、项目副本和元数据                 |

把快捷操作和模板逻辑拆到单独模块，减少对大型画布组件的改动。新增界面文字同时提供中文和英文。对话 Agent 与画板按钮继续使用同一套生成及保存机制。

## 8. 首版验收场景

| 场景                   | 预期结果                                         |
| ---------------------- | ------------------------------------------------ |
| 从图片拉线到空白处     | 在落点显示有效操作，取消后画板保持原状           |
| 从图片连到已有节点     | 原有引用连接行为继续正常工作                     |
| 选择描述操作           | 创建引用图片的文本节点，可直接运行并编辑结果     |
| 选择三视图并运行       | 得到三个独立图片节点和文件，无需左侧聊天         |
| 一个视角失败           | 其他成功结果保留，失败视角可以单独重试           |
| 选择生成模型           | 创建已关联参考图的现有 3D 节点，可配置并运行     |
| 未配置所需模型         | 显示具体缺失能力和设置入口，不静默失败           |
| 重新打开项目           | 节点、引用和已保存结果仍存在                     |
| Agent 随后操作这些节点 | 能继续读取、修改和执行，不出现两套互不兼容的数据 |

真实媒体验证需要用户已配置的可用服务商；界面和任务行为可以先使用模拟服务验证。截图中的鉴权失败另行排查，不把更换交互入口视为鉴权修复。

## 9. 待确认项

1. “获取图片内物体”的首版目标：识别清单后选择生成、直接分别重新生成，还是精确抠图？
2. 描述和提示词是否两个菜单项，还是一个文本节点里的可选模式？
3. 三视图是否仅提供固定俯视 / 正视 / 右视，还是首版就允许自选视角？
4. 批量生成共享参数的范围及默认并发数。
5. 后续自定义模板的重要性，是否要在首版保留扩展入口。

尚未确认的建议保持在讨论状态，不作为已经批准实现的范围。
